# Confirmation Dialog

**Components:** `Confirmation Dialog (Web) SDUI`, `Confirmation Dialog (Mobile) SDUI`
**Library:** DS Components SDUI Library (`eTFJFet7kxp4d8yFtPZfue`)

---

## When to use

- Use when the user must confirm a decision before it is executed.
- The dialog should restate the user's decision and summarize the consequences.
- It blocks all other interaction until dismissed — use sparingly.
- If the alert is auto-generated by the system and doesn't require user attention, use Toast or a banner instead.

---

## Anatomy

| Slot | Rule |
|---|---|
| Heading | Brief description of the dialog's purpose. |
| Body text | Restates the user's decision and its consequences. |
| Container | Holds dialog elements; separates from background via scrim. |
| Close button | Lets user exit without confirming or negating the action. |
| Divider | Separates content from buttons. |
| Primary button | The main action. If only one button, it is always Primary. |
| Secondary button | Dismissive action — e.g. "Cancel", "Remind me later". |
| Tertiary button | Ghost button — e.g. "Cancel", "Back", "Learn more". |
| Scrim | Overlays background to isolate the user from the current workflow. |

---

## Best practices

**Use sparingly.** Using dialogs incorrectly or too often diminishes purpose and salience — users learn to dismiss without reading. If the alert is auto-generated by the system and doesn't require user attention, use a banner or toast notification instead.

**Do:** Trigger a Confirmation Dialog for a deliberate user action that has consequences (e.g. "Your account is free — confirm to proceed").
**Don't:** Trigger a Confirmation Dialog for system-generated events like "Post successful" — use a Toast instead.

---

**Be simple and focused.** Confirmation Dialogs hold only a heading and body text. No forms, no complex content requiring outside context, no feature promotion. If the content needs more space, use a Modal or Navigation Panel instead.

**Don't:** Use a Confirmation Dialog to host a full form (e.g. "Edit address" with many fields).

---

**No nested dialogs.** One dialog must be dismissed before another can be triggered. This applies to any modal.

**Don't:** Trigger a second dialog ("Are you sure you want to leave?") from within an already-open dialog.

---

**Close icon ≠ secondary button.** They can perform different actions. The close icon always returns the user to main content with no changes. Example: primary = "Save changes", secondary = "Leave page", close = dismiss dialog while staying on page.

---

## Content rules

- **Heading:** Sentence case, lead with a verb where possible. Statement ("Message not sent") or question ("Save this post for later?"). No punctuation unless expressive (? or !).
- **Coordinate heading with primary button:** Use "Delete" not "Yes" — 1–3 words, verb-first, sentence case.
- **Body text:** Restate the decision and its consequences clearly.

---

## Interaction

- Always user-initiated — deliberate (e.g. clicking Delete) or indirect (e.g. closing a page with unsaved changes).
- Persistent until dismissed via buttons or close icon.
- `Esc` dismisses the dialog (same as pressing close button).
- When dismissed without navigating, focus returns to the element that triggered the dialog.

---

## Position

- Always horizontally centered.
- Vertically: centered in viewport, OR top-aligned with 128px top padding.

---

## Mobile

- Use `Bottom Sheet` as the default pattern for confirmation dialogs on native mobile.
- Use Native OS Alerts only if a Bottom Sheet is already active (to avoid closing it and losing unsaved work).

---

## Adaptability

- Grows vertically with content.
- At 400% zoom (effective viewport as small as 320×256): fills entire viewport. Heading, close icon, and buttons are sticky. Content area scrolls vertically if overflow.
- Content must not scroll both horizontally and vertically.

---

## Accessibility

**Focus order:**
1. Close button
2. Interactive elements in content area
3. Buttons, left to right (LTR)

**Keyboard:**
- `Esc` — dismisses dialog (same as close button)
- `Tab` — moves focus in sequence
- `Enter` — activates focused button

**Name, Role, Value:**
- Close button: Role = Button, a11y label = `"Close"`
- Action buttons: Role = Button, a11y label = visible label

**Color & Contrast:**
- All default colors meet minimum contrast for light and dark modes.
- Any content area customizations must also meet contrast requirements.
